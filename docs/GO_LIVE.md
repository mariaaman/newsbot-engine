# প্রডাকশনে যাওয়ার ধাপ (owner checklist)

## ১. ফাইল বসানো (ফোন থেকেও চলবে)
1. `newsbot-engine-update.zip` ইঞ্জিন রিপোর রুটে আপলোড করুন (Auto Unzip চালু থাকলে নিজে খুলে commit করবে)। **আগে ইঞ্জিন, পরে ব্রেইন।**
2. `newsbot-brain-update.zip` ব্রেইন রিপোর রুটে আপলোড করুন। এতে শুধু কনফিগ আছে, `state/`, `pending/` বা `content/` ছোঁয় না।
3. দুই রিপোতেই `.github/workflows/H` নামের ১ বাইটের ফাইলটি হাতে মুছুন (zip দিয়ে ফাইল মোছা যায় না)।
4. ইঞ্জিনের Actions-এ `ci` সবুজ হতে হবে।

## ২. যাচাই
1. Actions, `setup`, Run workflow: সব লাইন `OK`।
2. Actions, `readiness`, Run workflow: শেষ ধাপ `Scorecard`-এ `REVIEW-MODE VERDICT: READY` দেখুন। `FAIL` লাইনগুলো ব্লকার।
3. `hourly` হাতে চালান (mode ফাঁকা = review)। PR এলে GitHub অ্যাপে পড়ে merge/close করুন।

## ৩. কী বদলেছে
- OpenRouter-এর মৃত মডেল আইডি বাদ; Gemini এখন প্রথম, তারপর Groq, শেষে Workers AI।
- লেখক মডেল QA-তে নাম/সংখ্যায় আটকে গেলে নতুন আর্টিকেলের জন্য **একবার** পুনর্লিখনের সুযোগ পায়। গেট ঢিলে করা হয়নি: পুনর্লিখনও সব গেট পার হতে হবে।
- `unsupported_name` গেট এখন শিরোনামের সাধারণ শব্দ (`Exceeds`), পদবি (`Senator`) আর হাইফেনযুক্ত যৌগ শব্দ ঠিকভাবে বোঝে। বানানো নাম, দেশ ও নাগরিকত্ব এখনো আটকায়।
- `min_words` bn ২৫০, en ৩০০ (লেখক প্রম্পটের "৩০০ শব্দই যথেষ্ট"-র সঙ্গে মিলিয়ে)। কম শব্দের আর্টিকেল pending-এ যাবে।
- `state/decisions.jsonl` আর বাড়বে না: রুটিন SKIP লাইনের বদলে প্রতি রানে একটা সারাংশ লাইন; ফাইল ১ MB পার হলে পুরনো লাইন ছাঁটা হয়। প্রথম রানেই বর্তমান ২২ MB ফাইল কয়েক KB হবে।
- `readiness` workflow (নতুন), `unzip.yml` শক্ত করা (শুধু রুটে `.zip` push হলে চলে)।

## ৪. `auto` মোডে যাওয়ার শর্ত (readiness নিজেই মাপে)
- অন্তত ২০টি review PR merge হয়েছে, এবং merge-হার ৯০% বা বেশি।
- সর্বশেষ `hourly` রান সফল।
- Actions-এর `@v4`/`@v5` ট্যাগ (`VERIFY` মন্তব্য) commit SHA-তে pin করুন।

## ৫. AdSense
- প্রকাশিত আর্টিকেল ও ট্রাস্ট পেজ থাকলে তবেই আবেদন করুন। অনুমোদনের পর brain-এ `ads.enabled: true` ও `ads.publisher_id` দিন।

## ৬. ব্রেইন রিপোর আকার
- অতীতের `decisions.jsonl` সংস্করণগুলো git ইতিহাসে থেকে যাবে। Settings-এ রিপোর আকার দেখুন; খুব বড় হলে বর্তমান ফাইলগুলো দিয়ে নতুন private রিপো বানানো সবচেয়ে সহজ সমাধান।

## ৭. হার্ডনিং আপডেট (২০২৬-১০-২৯)
- **ক্রলারের পরিচয়:** আগে `NEWSBOT_CONTACT_URL` কোথাও সেট হতো না, তাই বট নিজেকে `example.invalid` বলে পরিচয় দিত (অনেক সাইট এমন বট আটকায়)। এখন ব্রেইনের `site.base_url` থেকে নিজে নেয়; হাতে সেট করলে সেটাই চলে।
- **নিরাপদ ফেচ:** ফিড ও আর্টিকেল ডাউনলোডে প্রতিটি রিডাইরেক্ট যাচাই হয় (শুধু http/https, লোকালহোস্ট/প্রাইভেট/মেটাডেটা আইপি নয়), ফিডের আকারেও সীমা আছে।
- **ডুপ্লিকেট চেক:** নতুন লেখার `শিরোনাম + সারাংশ` এখন আগের লেখার `শিরোনাম + সারাংশ`-এর সঙ্গে মেলানো হয় (আগে শুধু শিরোনামের সঙ্গে মেলানো হতো, তাই একই ঘটনার ভিন্ন শিরোনামের খসড়া ঢুকে যেত)।
- **ক্যাটেগরি:** মডেল `business`/`sport`/`tech`-এর মতো প্রতিশব্দ লিখলে নিশ্চিত মিল থাকলে সাইটের নিজের আইডিতে (`economy`/`sports`/`technology`) বদলে যায়। `legal`/`national`-এর মতো অনিশ্চিত মান আগের মতোই গেটে আটকায়।
- **`scripts/pending_triage.py <brain>`** (ব্রেইনের লোকাল কপিতে চালান, `--list` দিলে ফাইলের নাম দেখায়): `pending/` ড্রাফটকে চার ভাগে সাজায়: পড়ে অনুমোদন / পুনরায় যাচাই / পুনর্লিখন বা বাদ / ডুপ্লিকেট।
- **`pin-actions` workflow:** Actions ট্যাব থেকে একবার চালান। এটি সব `uses: ...@v4` লাইনকে ওই ট্যাগের আসল commit SHA-তে পিন করে commit করে (`WORKFLOW_PAT` লাগে)। তারপর `ci` ও `readiness` চালান।
- **Telegram approve Worker:** Cloudflare-এ `EDIT_PIN` secret সেট করুন (ঐচ্ছিক বলা আছে, কিন্তু রাখাই নিরাপদ)। ড্যাশবোর্ডে TOTP চালু করুন।
- **হাতে করণীয়:** দুই রিপো থেকে `unzip.yml` মুছুন কাজ শেষে (এবং `WORKFLOW_PAT` বাতিল করুন), আর AdSense-এর আগে নিজের ডোমেইন বসান (`site.base_url` বদলান)।

## ৮. অটো-মেরামত ও Adsterra (২০২৬-১০-৩০)
- **অটো-মেরামত:** কোনো লেখা গেটে আটকালে (ভুল নাম, বছর, বয়স, সংখ্যা, ছোট লেখা, ভুল উদ্ধৃতি/সাইটেশন, ক্যাটেগরি, নকল শব্দ, LLM-এর "অসমর্থিত দাবি") লেখককে ঠিক কী ভুল তা জানিয়ে আবার লেখানো হয়, সর্বোচ্চ `qa.max_repair_attempts` বার (ডিফল্ট ২, `0` = বন্ধ)। প্রতিবার সব গেট ও LLM যাচাই আবার চলে। কোনো গেট ঢিলা হয়নি। সব গেট পাস করলে `auto` মোডে লেখা নিজে প্রকাশ হয় (`review` মোডে PR)।
- যা মেরামত হয় না (লেখার ভুল নয়): `schema`, `source_not_fetched`, `no_sources`, `duplicate_title`, `duplicate_embedding`, `no_change`, `correction_unsupported`। এগুলো `pending/`-এ কারণসহ থাকে।
- **স্পর্শকাতর বিষয়** (মৃত্যু, অপরাধ, স্বাস্থ্য, নির্বাচন, ধর্ম, শিশু, আর্থিক পরামর্শ) গেট পাস করলেও মানুষ দেখার জন্য `pending/`-এ যায়। সম্পাদকীয় নীতির পাতায় এটাই প্রতিশ্রুতি।
- মেরামতে বাড়তি LLM খরচ হয় (প্রতি ব্যর্থ লেখায় সর্বোচ্চ ২টি করে অতিরিক্ত লেখা)। দৈনিক টোকেন বাজেট ফুরোলে মেরামত থামে।
- **Adsterra:** `docs/ADSTERRA.md` দেখুন।

## ১০. কাটা-পড়া উত্তর ও রানের সময়সীমা (২০২৬-১০-৩১)
- **কারণ:** `verify` ধাপের JSON উত্তর (সাতটা সোর্স x প্রায় ৩০ দাবি) `max_tokens=5000`-এ কেটে যাচ্ছিল (gpt-oss নিজে ভাবতেও টোকেন খরচ করে)। কাটা JSON অবৈধ, আর "ঠিক করো" অনুরোধে একই সীমা ও ভাঙা উত্তর আবার যাওয়ায় আবার কাটত, ফলে গল্প `llm_failed` হতো (দুই অ্যাকাউন্টে প্রায় ৯০০ নিউরন নষ্ট)।
- **ফিক্স:** (১) `verify`-এর জায়গা দাবির সংখ্যা অনুযায়ী (`3000 + 40 x দাবি`, সর্বোচ্চ ১২০০০)। (২) উত্তর `finish_reason=length`-এ কাটলে ভাঙা উত্তর না পাঠিয়ে একই প্রশ্ন আবার করা হয় ১.৮ গুণ জায়গা দিয়ে (সর্বোচ্চ ১৪০০০, একবারই)। (৩) `limits.max_run_minutes` (ডিফল্ট ২২): এরপর নতুন LLM কাজ শুরু হয় না, গল্প কিউতে থাকে, রান নিজে শেষ হয়ে `commit` করে। (৪) `hourly`-এ টোকেনসহ অ্যাকাউন্ট-ফাইল `Run engine`-এর পরেই মুছে যায়।
